## 빠진 건물번호를 알아차린 때

한 고객이 입력한 주소가 자동으로 바뀌면서 건물번호가 빠진 채 저장됐다고 문의했습니다. 고객감동팀과 물류기획팀이 배송사에 확인했을 때는 이미 반송이 시작된 뒤였습니다. 이 시점에는 주소를 고쳐도 그 배송을 되돌릴 수 없었습니다.

입력을 시작하는 위치, 국가별로 필요한 정보, 저장 뒤 고객에게 보여줄 주소를 주문서 안에서 한 흐름으로 묶었습니다.

## 국가를 고르면 입력 순서가 달라집니다

주소를 한 줄로 받으면 어떤 정보가 빠졌는지 고객도 알아보기 어렵습니다. 홍콩에서는 검색한 건물에 층과 호를 덧붙이고, 대만에서는 지역을 선택하면 그에 연결된 우편번호를 보여줍니다. 주소를 찾는 단서와 직접 적어야 할 정보가 각각 다르기 때문입니다.

| 국가·지역 | 경험을 나눈 기준 |
| --- | --- |
| 한국 | 기본주소를 검색해 선택한 뒤 상세주소를 입력 |
| 중국 | 성에서 시, 구·현 순으로 지역을 좁힌 뒤 상세주소를 입력 |
| 대만 | 시·현과 구를 고르면 연결된 우편번호를 표시 |
| 홍콩 | 건물을 검색한 뒤 층과 호를 별도 항목으로 입력 |
| 일본 · 추후 반영안 | 우편번호로 지역을 찾고 번지와 건물명을 입력 |

## 저장한 주소를 주문서에서 다시 읽기

주문서의 배송 정보에서 ‘배송지 입력’을 누르면 국가를 선택할 수 있습니다. 해당 국가에 필요한 항목을 보여주고, 입력 오류는 고칠 필드 옆에서 안내합니다. 저장하고 돌아온 주문서에서는 주소와 송장에 쓰일 영문 표기를 함께 읽을 수 있습니다. 빠진 정보를 발견하면 ‘변경’에서 해당 배송지를 다시 엽니다.

[예시 배송지 입력해 보기 →]({{ '/assets/work/address-demo.html' | relative_url }})

체험에서는 가상 건물과 호수를 선택합니다. 같은 배송지를 다른 호수로 변경해 보면 주문서의 두 주소가 어떻게 바뀌는지 확인할 수 있습니다.

## 물류팀이 관찰한 변화

물류기획팀이 확인한 이벤트당 주소 오류 최대 건수는 이전 약 400건, 최근 약 30건이었습니다. 오류가 한 건도 없는 이벤트도 있었습니다. 각 기간에 오류가 가장 많았던 이벤트를 비교한 수치입니다.
