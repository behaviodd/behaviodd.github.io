## 색상에 이름을 붙이는 일부터

색상, 크기, 간격, 글꼴을 변수로 관리하기 전에 이름과 위계를 정했습니다. 같은 색이라도 색상값 자체를 가리킬 때와 특정 UI 요소에 적용할 때의 이름을 나누었습니다. 예를 들어 `#C5202E`는 기초 토큰 `red.40`에 담고, 빨간 텍스트에는 용도를 드러내는 `color.text.red.default`를 연결했습니다.

이 구조에서는 기초 토큰 값을 한 번 바꾸면 연결된 색상을 함께 변경할 수 있습니다. 디자이너와 개발자, 외부 파트너가 같은 UI 요소를 이야기할 때도 토큰 이름을 기준으로 대화할 수 있었습니다.

## 밝은 화면과 어두운 화면에서 일관된 위계

웹 접근성 기준을 고려해 HSL 기반의 컬러 팔레트를 만들었습니다. 라이트 모드와 다크 모드의 색상 번호를 대응시켜 엔지니어가 번호로도 적용할 색상을 유추할 수 있게 했습니다. 아이콘은 서비스에 필요한 기능을 담아 직접 제작하고, 크기와 선 두께를 통일했습니다.

![라이트·다크 모드의 색상 위계와 텍스트 대비를 검토한 삼분의일 컬러 팔레트]({{ '/assets/work/third-system-colors.png' | relative_url }})

## 재사용 컴포넌트로 출시하기

텍스트 입력, 버튼, 체크박스, 다이얼로그 같은 요소를 모듈화하고 기능과 속성 옵션을 문서화했습니다. 하나의 컴포넌트를 어디에 어떻게 쓸지 팀이 직접 찾아볼 수 있게 했습니다.

시스템을 배포한 뒤에는 별도 화면 디자인 없이 개발 정책 문서와 기존 컴포넌트만으로 신규 기능을 출시한 사례가 있었습니다. 삼분의일 온라인 체험관 리뉴얼은 프로젝트 시작부터 사용자 출시까지 6주가 걸렸습니다.
