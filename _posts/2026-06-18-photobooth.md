## 왜 만들었나

인생네컷은 부스 앞에 줄을 서야 찍을 수 있습니다. 카페에서, 집에서, 팬 이벤트 현장에서 그 감성을 그대로 쓰고 싶은데 부스는 거기 없습니다.

휴대폰 카메라로 찍어서 앱으로 합치면 되긴 합니다. 문제는 그 과정이 **부스에서 찍는 것과 전혀 다른 경험**이라는 점입니다. 부스는 버튼을 누르면 알아서 카운트다운이 돌고 네 번 찍히고 인화됩니다. 고를 것도, 기다릴 것도 없습니다. 그 리듬이 결과물만큼 중요합니다.

그래서 만든 건 사진 합성 도구가 아니라 **부스의 리듬을 웹으로 옮긴 것**에 가깝습니다.

---

## 무엇을 만들었나

**링크 열면 바로 촬영입니다.** 랜딩도 설정 화면도 없습니다.

**네 컷이 자동으로 찍힙니다.** 카운트다운이 돌고, 네 번이 끝나면 꾸미기 화면으로 넘어갑니다.

**꾸미는 건 찍고 나서 합니다.** 프레임과 필터를 결과 화면에서 바꿉니다.

**저장·공유·인쇄가 됩니다.** 1200×3600 고해상도 PNG로 뽑고, 공유 시트나 인쇄 대화상자로 바로 넘길 수 있습니다.

---

## 판단이 필요했던 순간들

### 1. 랜딩 페이지를 지운 것

처음엔 정석대로 만들었습니다. 랜딩에서 시작하기를 누르고, 모드를 고르고, 스타일을 고르고, 프레임을 고른 뒤 촬영으로 들어갑니다.

전부 지웠습니다. 지금은 주소를 열면 **곧바로 카메라 화면**이고, 권한이 이미 허용돼 있으면 라이브 프리뷰가 바로 뜹니다. 실제 부스에는 시작 버튼이 없습니다. 앞에 서면 그게 시작입니다. 선택지를 앞에 늘어놓는 건 만드는 사람에게 편한 구조지, 찍으러 온 사람에게 편한 구조가 아니었습니다.

### 2. 꾸미기를 촬영 뒤로 옮긴 것

원래 순서는 스타일과 프레임을 먼저 고르고 찍는 것이었습니다. 데이터 흐름상으로도 그게 자연스럽습니다. 필터를 정해놓고 찍으면 합성이 한 번이면 되니까요.

하지만 찍기 전에는 무엇이 어울릴지 알 수 없습니다. 표정도 배경도 아직 없는데 파스텔이 나을지 흑백이 나을지 어떻게 정합니까. 그래서 **찍고 → 꾸미기** 로 뒤집었습니다. 대가는 결과 화면에서 프레임이나 필터를 바꿀 때마다 캔버스를 다시 합성해야 한다는 것입니다. 저장·공유·인쇄가 전부 현재 선택 기준으로 매번 다시 합성됩니다. 연산을 더 쓰는 대신 사용자가 되돌아갈 일이 없어졌습니다.

### 3. 카메라 실패를 다섯 가지로 나눈 것

`getUserMedia`는 여러 이유로 실패합니다. 하나로 뭉뚱그려 "카메라를 사용할 수 없습니다"라고 띄우면 사용자는 무엇을 해야 할지 모릅니다.

그래서 원인을 다섯으로 나눴습니다 — 권한 거부, 카메라 없음, 다른 앱이 사용 중, 브라우저 미지원 또는 비보안 컨텍스트, 그리고 나머지. 각각 안내가 다릅니다. 권한 거부는 설정에서 바꾸면 되고, 다른 앱이 쓰는 중이면 그 앱을 닫으면 되고, 미지원이면 아무리 해도 안 됩니다. **마지막 경우에는 사진 업로드 모드로 우회**시킵니다. 같은 네 장을 올리면 결과물은 똑같이 나옵니다. 카메라가 이 서비스의 전제이긴 하지만, 유일한 입구일 필요는 없었습니다.

### 4. 미리보기와 결과물의 좌우를 맞춘 것

카메라 프리뷰는 거울처럼 좌우를 뒤집어 보여줍니다. 그래야 사람이 자기 움직임을 자연스럽게 인식합니다. 그런데 실제로 캡처되는 프레임은 뒤집히지 않은 원본입니다.

이대로 두면 **화면에서 본 것과 저장된 사진이 좌우가 다릅니다.** 글자가 있는 옷을 입었으면 바로 티가 납니다. 그래서 캡처할 때 프리뷰와 같은 방향으로 뒤집어 저장하고, 촬영 화면 구석에 `전면 카메라 · 미러` 라고 적어 지금 보고 있는 게 거울상이라는 걸 알려줍니다. 물리 부스는 이런 고민이 없는데, 화면을 거쳐야 하는 매체에서는 "보이는 것"과 "찍히는 것"을 일부러 일치시켜야 합니다.

### 5. 디자인을 여섯 번 갈아엎은 것

이 저장소의 커밋 이력은 절반이 디자인 교체입니다. 동화풍 라인 일러스트 → macOS 데스크톱 스타일 → 그림자 없는 각진 UI → 흰색·검정·포인트 컬러의 모던 → 그리고 이름까지 바꾼 리브랜딩.

기능은 3번 커밋쯤에서 이미 다 돌아갔습니다. 나머지는 전부 "이게 맞는 톤인가"를 확인하는 과정이었습니다. 언어도 네 개(한/중/일/영)로 만들었다가 **영어와 일본어만 남겼습니다.** 넓게 지원하는 것보다 어떤 사용자를 상정하는지가 분명한 편이 화면을 만들기 쉬웠습니다. 코드가 아니라 톤을 정하는 데 시간을 쓴 프로젝트였고, 그건 낭비가 아니라 이 제품에서 정해야 할 것이 그쪽이었기 때문입니다.

## AI가 한 것 / 내가 한 것

**AI가 잘한 것.** `getUserMedia` 래핑과 상태 기계, 카운트다운, 캔버스 합성(여백·간격·푸터 계산), 업로드 모드의 cover-crop, 오브젝트 URL 해제 같은 누수 처리, 다국어 구조. 특히 디자인을 통째로 갈아엎을 때마다 전 화면을 일관되게 다시 칠해주는 속도가 이 프로젝트의 진행 방식 자체를 바꿨습니다. 톤을 여섯 번 바꿔볼 수 있었던 건 한 번 바꾸는 비용이 쌌기 때문입니다.

**넘길 수 없었던 것.** 랜딩을 지우자는 결정입니다. 화면을 하나 없애는 건 기능을 빼는 일이라 AI가 먼저 제안하지 않습니다. "부스 앞에 서면 그게 시작"이라는 감각은 부스를 써본 사람만 갖고 있습니다.

꾸미기를 뒤로 옮긴 것도 마찬가지입니다. 구현 관점에서는 명백히 손해인 순서고, 그 손해를 감수할 이유는 사용자가 무엇을 언제 판단할 수 있는지에서 나옵니다. 만드는 순서와 쓰는 순서가 다를 때 어느 쪽을 따를지는 매번 사람이 정해야 합니다.

## 회고

### 잘된 점

- **사진이 기기를 벗어나지 않는 것.** 서버가 없으니 저장 정책도, 유출 위험도 없습니다. 탭을 닫으면 끝입니다.
- **실패에 우회로를 둔 것.** 카메라가 안 되는 사용자도 업로드로 같은 결과물을 얻습니다.
- **톤을 여러 번 시도해본 것.** 결과적으로 처음 방향과 전혀 다른 곳에 도착했고, 그게 더 나았습니다.

### 개선할 점

- 도메인이 아직 배포 기본 주소 그대로입니다. 링크로 공유하기엔 이름이 안 붙어 있습니다.
- 프레임이 세 종류뿐이라, 이벤트용으로 쓰려면 커스텀 프레임이 필요합니다.
- 인쇄는 숨은 iframe으로 인쇄 대화상자를 여는 방식이라 용지 여백까지는 제어하지 못합니다.
- 리브랜딩 이후 문서(기획·디자인 문서 6종)가 옛 이름과 옛 방향을 그대로 두고 있습니다.

## 촬영

```
useCamera
  status : idle → requesting → ready | error
  error  : denied | notfound | inuse | unsupported | unknown
  capture(): 현재 프레임을 JPEG data URL로
             ※ 프리뷰와 같은 방향으로 미러링해서 저장
```

에러 다섯 종은 각각 다른 안내로 이어지고, `unsupported` · `notfound` 는 업로드 모드로 우회시킵니다.

## 스트립 합성

```
STRIP_W = 1200
STRIP_H = 3600
PAD     = 60    // 좌·우·상단 여백
GAP     = 20    // 사진 사이 간격
FOOTER  = 150   // 워드마크 + 날짜

CELL_W = STRIP_W - PAD * 2
CELL_H = (STRIP_H - PAD - FOOTER - GAP * 3) / 4
```

합성은 렌더 경로 밖에서 돌리고 결과 PNG를 오브젝트 URL로 노출합니다. 새 결과로 교체되거나 언마운트될 때 이전 URL을 해제해 누수를 막습니다. 저장·공유·인쇄는 전부 **현재 선택된 프레임과 필터 기준으로 그때그때 다시 합성**합니다.

프레임은 `sweet-pink` · `mint-diary` · `lavender-ticket` 세 종이고, 필터는 컬러 · 흑백 · 파스텔입니다.

## 진행 단계

**Phase 1~2** — Vite + React + TS 스캐폴딩, 기획 문서 6종, mock 데이터로 전 화면 뼈대.

**Phase 3** — `getUserMedia` 실제 촬영. 에러 분기와 권한 게이트.

**Phase 4** — 업로드 모드(cover-crop · 순서 변경 · 추가/삭제).

**Phase 5** — 캔버스 합성과 PNG 다운로드.

**Phase 6** — UX 재설계. 랜딩 제거, 자동 4컷, 찍고 나서 꾸미기로 순서 반전.

**Phase 7** — 배포. 남은 건 QA와 도메인 정리.
